# 1. Objetivo

La Inteligencia Artificial será un asistente financiero personal.

Su función será ayudar al usuario a comprender mejor sus finanzas, automatizar tareas repetitivas y responder dudas.

La IA nunca sustituirá el control del usuario.

---

# 2. Filosofía

La IA debe cumplir siempre los siguientes principios.

- Ayudar, no decidir.
- Explicar, no ocultar.
- Automatizar tareas repetitivas.
- Nunca modificar datos sin confirmación.

El usuario siempre tendrá la última palabra.

# 4. Proveedor IA

La V0 utilizará Groq.

Cada usuario deberá introducir su propia API Key.

La aplicación nunca compartirá claves entre usuarios.

En futuras versiones podrán añadirse otros proveedores sin modificar el resto de la aplicación.

Ejemplos:

- Groq
- OpenAI
- Gemini
- Ollama

# 5. Funcionalidades

## Chat financiero

El usuario podrá realizar preguntas como:

- ¿En qué gasto más dinero?
- ¿Cuánto he gastado este mes?
- ¿Cómo puedo ahorrar?
- ¿Qué suscripciones tengo activas?
- ¿Cuánto gasto en gasolina?

La IA responderá utilizando los datos almacenados en la aplicación.

**Hecho**: está en la pestaña IA. Usa `openai/gpt-oss-120b` en Groq (plan gratuito: unas 1.000 preguntas al día,
con un cupo distinto del modelo de los tickets, `qwen/qwen3.8-27b`). Cada pregunta manda un resumen de unos
cientos de tokens (últimos tres meses, pagos y cobros fijos, objetivos) y los 6 últimos mensajes. La conversación
solo vive en la app: se pierde al cerrarla. El modelo se cambia con `app.ia.groq.modelo-chat`.

---

## Consejos

Cuando el usuario abra el chat, la IA podrá mostrar un pequeño resumen.

Ejemplos:

- "Este mes llevas gastado un 45 % del presupuesto."
- "Has reducido el gasto en ocio respecto al mes pasado."
- "Recuerda que el día 25 se cargará Netflix."

No aparecerán mensajes automáticos fuera del chat.

---

## Clasificación automática

La IA podrá sugerir:

- Categoría.
- Etiquetas.
- Descripción.

El usuario decidirá si acepta la propuesta.

---

## Resúmenes

La IA podrá generar:

- Resumen mensual.
- Resumen anual.
- Evolución financiera.
- Gastos destacados.

# 6. Memoria financiera

La IA dispondrá de una memoria basada únicamente en los datos de la aplicación.

Podrá recordar:

- Categorías frecuentes.
- Etiquetas habituales.
- Patrones de gasto.
- Objetivos de ahorro.
- Vehículos registrados.

No almacenará conversaciones personales fuera del contexto financiero.

# 7. OCR de tickets

El usuario podrá crear un movimiento mediante una fotografía.

Proceso:

1. El usuario hace una foto al ticket.
2. La imagen se envía al backend.
3. El backend llama a la IA.
4. La IA extrae la información.
5. Se muestran los datos al usuario.
6. El usuario revisa los datos.
7. El usuario confirma la creación del movimiento.

La IA nunca creará un movimiento automáticamente.

## Base ya implementada (noviembre 2026)

El backend ya cubre la parte del flujo que no depende de la IA:

- `POST /api/tickets` crea el ticket (fecha, comercio, importe, descripción).
- `POST /api/tickets/{id}/imagen` guarda la foto (JPG, PNG o WEBP, máximo 5 MB).
- `POST /api/tickets/{id}/gasto` convierte el ticket en un gasto una vez revisado (paso 7).

Cuando se añada el OCR, el paso 3 leerá la imagen ya guardada y propondrá los datos del ticket. El usuario seguirá confirmando con la conversión en gasto, así que la regla "la IA nunca crea un movimiento sola" se mantiene.

# 8. Seguridad

- La API Key se almacenará cifrada.
- Nunca se mostrará completa.
- Nunca se enviarán datos innecesarios al proveedor IA.
- Toda comunicación utilizará HTTPS.
